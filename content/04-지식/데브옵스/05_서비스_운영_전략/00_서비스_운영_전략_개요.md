# 서비스 운영 전략 개요

## 왜 필요한가?

서비스를 배포한 이후에도 **안정적으로 유지**하고 **다운타임 없이 변경**을 적용하는 것이 현대 운영의 핵심이다.

---

## 주요 개념 맵

```
서비스 운영 전략
├── 이중화 (Redundancy)         → 단일 장애점(SPOF) 제거
├── 로드밸런싱 (Load Balancing) → 트래픽 분산
├── A/B 테스트                  → 기능 검증, 점진적 배포
├── 무중단 배포                 → 서비스 중단 없이 릴리스
└── 장애대응 / Failover         → 장애 발생 시 자동 전환
```

## 연관 개념

- **가용성 (Availability)**: 99.9% (3-nines) = 연간 8.7시간 다운타임
- **SLA / SLO / SLI**: 서비스 수준 협약 / 목표 / 지표
- **MTTR / MTBF**: 평균 복구 시간 / 평균 장애 간격
